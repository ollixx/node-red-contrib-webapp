# P27 — De-hardcode the runtime — node-driven demo behaviour and data

## Result

**Delivered:** Removed the Customers-specific demo backend baked into nodes/webapp.js so the runtime entry point is example-agnostic (grep-clean of 'customer'/'/customers'). Dialog open/close, CRUD persistence, query refresh and navigation now all flow through generic, config-driven typed actions: dropped the openCustomerEditor/closeCustomerEditor/saveCustomer/deleteCustomer/openCustomerDetail/goToCustomers if-branches and the allowLegacyPreviewAction allow-list; deleted createDemoQueryData, customerDraftFromRecord and nextCustomerId (replaced by a generic nextRecordId). Demo data is now seeded from ui-query.previewData (new schema field, mounted under the query's collection root) via seedQueryDataFromConfig. Two new generic action types — submit (upsert a record from input values + draft into a collection, then close its dialog) and remove (delete a record by key from a collection, optional redirect) — implemented as applySubmitAction/applyRemoveAction, driven by new ui-action config fields (collection, keyField, draftPath, dialog). The served dialog Close link is now derived from the hide action targeting that dialog (findDialogCloseAction) instead of a hard-coded pair; the '/customers' location fallbacks were replaced with '/' and a model-derived default route (defaultRouteLocation). Latent bug fixed: ui-button mapConfig silently dropped the `action` field, so config-driven action references never worked (the old demo only worked by id-coincidence with the hard-coded branches).

**Stats:** 8 files changed (nodes/webapp.js, packages/schema/src/{contracts,node-definitions}.ts, packages/runtime/src/node-set.ts, packages/schema/src/fixtures.ts, scripts/gen-example.js, nodes/behavior/ui-action.html, nodes/state/ui-query.html), 1 new test file (packages/runtime/test/p27-de-hardcode.test.ts, 8 tests), 2 tests rewritten (ui-action-runtime, customers-crud-example), docs updated (ui-action.md, ui-query.md), p22 e2e fixture + example flow regenerated. Unit suite: 173 tests, 0 failures.

**Notes:** actionTypeSchema extended with submit|remove — low-risk, the renderer does not switch on actionType values. The example (fixtures.ts + gen-example.js) was migrated to the generic action types (openCustomerEditor→show, closeCustomerEditor→hide, saveCustomer→submit, deleteCustomer→remove) and given previewData so its behaviour is now node-driven; the full from-scratch rebuild of the example surfaces (populated home route, visual catalogue) remains P28. customers-crud-example.test.ts navigations assertions updated because deleteCustomer is no longer a navigate action. E2E: the customers-crud and p21-detail specs were already red on the P26 baseline (verified by stash-and-rerun) — they depend on the example-flow rebuild owned by P28; P27 fixed the 2 p22 specs it had impacted (by migrating the p22 fixture to generic actions + previewData) and introduces no new e2e failures. The editor-spec failures (p16d/editor-mount-options/parent-selector) are the same pre-existing bare-editor flake. Manual CRUD smoke (list seed, open/save/delete/detail-nav) verified end-to-end through node-driven actions. See .ai/friction-log.md for the dropped-button-action find.
