# Friction Log

Raw material for the `review-agent-os` role. Whenever something in the agent-OS,
the docs, or the workflow **slowed you down, misled you, or caused rework**, append
one line here before you finish your task. Be specific and point at the file.

This is not a bug tracker for the product — it is a log of friction in *how we work*.
Newest at top. The review role mines this list and prunes entries once addressed.

Format:

```
- YYYY-MM-DD [role] what was wrong/misleading + where (file:line or path)
```

## P44 (2026-06-04)
- **Node-RED 4 config-node trap**: Nodes without x/y coordinates are categorized as "config nodes" by Node-RED's flow parser — not documented anywhere in the E2E setup notes. Caused inject nodes to never register, producing 404s. Fix: add x/y to all FlowBuilder nodes.
- **`setFlows` fire-and-forget start**: Node-RED 4's `setFlows` returns the revision before nodes are started (`start()` is fired with `.then()` not `await`). This means `POST /flows` 204 response arrives before inject nodes are registered. Fix: retry loop in `injectMessage`.
- **readDeployDefinitions ignores in-memory patches**: The `viewNodePatchInputHandler` patches `registration.definition` in memory, but `readDeployDefinitions` reads from the flow file on disk — so SSE snapshots always reflect the original value. This was a silent P39 bug that only surfaced in P44 tests. Fix: merge `definition.value` from live registration.
- **FlowBuilder missing required `value` field**: Interactive node schemas require `value: bindingSchema` but FlowBuilder didn't provide defaults — causing silent Zod validation failures and nodes never registering. Fix: add literal binding defaults.
- **Serializer missing disabled on sl-input/select/textarea/datepicker**: Only sl-checkbox and sl-switch had explicit `disabled` attribute rendering. The other form controls silently ignored the disabled binding. Fix: add `const disabled = component.disabled ? " disabled" : ""` in each branch.
- **P45: parseList vs parseJsonList mismatch in mapConfigs**: accordion/tabs/menu/stepper/table all used parseList for JSON-array string inputs, comma-splitting the JSON into garbage. context-budget.md doesn't call out this pattern as a known pitfall — a note about "when to use parseJsonList" would have saved multiple debug cycles.
- **P45: Zod strips unknown fields silently**: listItemSchema and menuItemSchema were missing id/route/href fields — Zod validation strips unknown props without warning, causing rendered output to lose those fields. No indication in architecture.md or context-budget.md to check schema stripping when adding new node tests.
P46 (2026-06-04): FlowBuilder nodes without x/y coordinates are silently treated as config nodes by Node-RED, causing 'Circular config node dependency' errors and /inject/:id 404s. The context-budget.md gives no hint about this Node-RED internals requirement. Debugging took significant time because the error only appeared in the NR log, not in the test output.
- P47: scope specified openNode "double-clicks the node on canvas", but the established repo pattern (editor-mount-options.spec.ts, parent-selector.spec.ts) opens panels via RED.editor.edit(RED.nodes.node(id)). Used the proven API path; double-click resolves to the same call but is flakier. Also undocumented: Node-RED 4.x shows a first-run welcome-tour overlay that intercepts editor clicks (had to dismiss via Escape), and the Done button is #node-dialog-ok in the tray toolbar (not a footer .primary button). A note in the editor-test context-budget would have saved a round of debugging.
